# Как включить настоящий сервер: регистрация по почте, вход с кодом в Telegram или через Google

Всё бесплатно. Займёт около 30–40 минут. Делается один раз.

Пока вы это не сделаете, сайт работает как раньше, в демо-режиме (код «из SMS» показывается прямо на экране, всё хранится только в телефоне).

## Как человек будет регистрироваться и входить

**Регистрация (один раз):**
1. Нажимает «Зарегистрироваться по почте» и пишет свою почту.
2. На почту приходит код из 6 цифр. Человек вписывает его на сайте. Так мы знаем, что почта его.
3. Пишет своё имя.
4. Нажимает «Подключить Telegram»: открывается наш бот, человек жмёт «Старт» и «Поделиться номером». Так подтверждается номер телефона, а бот запоминает, куда слать коды.

**Вход (каждый раз):**
1. Человек пишет свою почту и нажимает «Получить код в Telegram».
2. Бот присылает в Telegram код из 6 цифр. Код живёт 5 минут, подходит один раз, после 5 неверных попыток сгорает.
3. Человек вписывает код на сайте и входит. Бот сразу пишет «Выполнен вход». Если это был не он, под кодом есть кнопка «Это не я», а в профиле «Выйти на всех устройствах».

Если человек при регистрации нажал «Позже» и Telegram не подключил, он входит кодом из письма. Как только Telegram подключён, войти одним кодом с почты уже нельзя: нужен код из Telegram. Поэтому тот, кто украл или угадал почту, в аккаунт не попадёт.

**Вход через Google (для тех, у кого нет Telegram):**
1. Человек нажимает «Войти через Google», выбирает свой Google-аккаунт и возвращается на сайт.
2. Если аккаунта с этой почтой ещё нет, он создаётся сам. Имя подставляется из Google, его можно поправить. Подключать Telegram не обязательно.
3. Если к аккаунту с этой почтой уже подключён Telegram, правило то же, что с почтой: бот присылает код, и без него войти нельзя.

Регистрация по почте и через Google ведёт в один и тот же аккаунт, если почта одна и та же.

## Шаг 1. Создать Telegram-бота (5 минут)

1. Откройте Telegram и найдите **@BotFather** (с синей галочкой).
2. Отправьте ему `/newbot`.
3. Он спросит имя. Напишите, например: `go-transfer-go вход`.
4. Он спросит адрес бота. Он должен заканчиваться на `bot`, например: `gotransfergo_login_bot`.
5. BotFather пришлёт **токен**: длинную строку вида `7123456789:AAH...`.
   **Это секрет.** Никому его не пересылайте, в том числе мне, и не вставляйте в GitHub. Он понадобится в шаге 5.
6. Отправьте BotFather `/setjoingroups` → выберите бота → **Disable**. Так бота нельзя добавить в чужие группы.

## Шаг 2. Создать проект Supabase (5 минут)

1. Зайдите на **supabase.com** → **Start your project** → войдите через GitHub.
2. **New project**:
   - Name: `go-transfer-go`
   - Database Password: нажмите **Generate**, сохраните пароль у себя (в заметки или менеджер паролей).
   - Region: **Central EU (Frankfurt)**. Данные европейцев должны храниться в ЕС.
   - Тариф **Free**.
3. Подождите 1–2 минуты, пока проект создаётся.

## Шаг 3. Создать таблицы (2 минуты)

1. Слева **SQL Editor** → **New query**.
2. Откройте файл [`supabase/schema.sql`](supabase/schema.sql) в репозитории на GitHub, нажмите кнопку «Copy raw file» (две квадратные рамки) и вставьте всё в окно Supabase.
3. Нажмите **Run**. Должно появиться `Success. No rows returned`.

## Шаг 4. Включить вход

1. Слева **Authentication** → **Sign In / Providers** (или **Settings**).
2. Включите **Allow anonymous sign-ins** и нажмите **Save**. Это нужно для технической сессии до входа. Пока человек не вошёл, он ничего не может ни прочитать, ни опубликовать.
3. Там же проверьте, что **Email** включён (по умолчанию так и есть).
4. **Authentication** → **Rate Limits**: оставьте значения по умолчанию (не увеличивайте). Они не дают ботам создавать тысячи сессий и рассылать письма.
5. **Капчу (Attack Protection → CAPTCHA) пока не включайте.** Сайт ещё не умеет её показывать, и вход перестанет работать. Добавим её, когда переедем на свой домен.

## Шаг 5. Загрузить функцию входа через Telegram (5 минут)

1. Слева **Edge Functions** → **Deploy a new function** → **Via Editor**.
2. Имя функции: `tg-login` (ровно так).
3. Удалите пример кода, откройте [`supabase/functions/tg-login/index.ts`](supabase/functions/tg-login/index.ts) на GitHub, скопируйте и вставьте всё.
4. Нажмите **Deploy function**.
5. Откройте функцию → **Details** (или **Settings**) → выключите **Enforce JWT verification** / **Verify JWT** → **Save**.
   Это нужно, потому что сообщения от Telegram приходят без ключа Supabase. Функция сама проверяет каждое сообщение секретом из следующего пункта.
6. Слева **Edge Functions** → **Secrets** → добавьте три секрета:

   | Name | Value |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен из шага 1 |
   | `TELEGRAM_WEBHOOK_SECRET` | придумайте длинный пароль из латинских букв и цифр, 30+ символов, без пробелов. Например, наберите случайно на клавиатуре. |
   | `ALLOWED_ORIGIN` | `https://autovinzare-code.github.io` |

7. Подключите бота к функции. Откройте в браузере адрес (подставьте своё):
   ```
   https://АДРЕС-ПРОЕКТА.supabase.co/functions/v1/tg-login?setup=ВАШ_TELEGRAM_WEBHOOK_SECRET
   ```
   Адрес проекта смотрите в **Project Settings → Data API → Project URL**.
   Должно появиться: **«Готово! Бот @… подключён.»**

## Шаг 6. Письма с кодом регистрации (10 минут)

Без этого шага регистрация не заработает. Встроенная почта Supabase отправляет всего пару писем в час и только вам самим. Поэтому подключаем бесплатный сервис писем **Brevo** (300 писем в день бесплатно).

1. Зарегистрируйтесь на **brevo.com** (тариф Free).
2. **Senders, Domains & Dedicated IPs** → **Senders** → добавьте адрес, с которого будут идти письма (например, ваш Gmail), и подтвердите его по ссылке из письма.
3. Справа вверху меню → **SMTP & API** → вкладка **SMTP**: там указаны сервер `smtp-relay.brevo.com`, порт `587`, логин, и кнопка **Generate a new SMTP key**. Создайте ключ.
4. В Supabase: **Authentication** → **Emails** → **SMTP Settings** → включите **Enable custom SMTP** и впишите:
   - Sender email: адрес из пункта 2
   - Sender name: `go-transfer-go`
   - Host: `smtp-relay.brevo.com`, Port: `587`
   - Username: логин из Brevo, Password: SMTP-ключ из Brevo
   - **Save**
5. Там же **Authentication** → **Emails** → **Templates**. В шаблонах **Magic Link** и **Confirm signup** замените текст на:
   - Subject: `Код подтверждения go-transfer-go`
   - Body:
     ```html
     <h2>Ваш код: {{ .Token }}</h2>
     <p>Введите его на сайте go-transfer-go. Код действует 10 минут.</p>
     <p>Никому не сообщайте этот код. Если вы ничего не делали на сайте, просто удалите это письмо.</p>
     ```
   Без этого в письме будет ссылка вместо кода.
6. **Authentication** → **Sign In / Providers** → **Email** → **Email OTP Expiration**: поставьте `600` (10 минут) → **Save**. Так украденный старый код быстро становится бесполезным.

## Шаг 7. Подключить сайт к серверу (2 минуты)

1. В Supabase: **Project Settings** → **API Keys**. Скопируйте **Publishable key** (`sb_publishable_...`) или, если его нет, ключ **anon public**.
   **Не берите** ключ `secret` / `service_role`: он даёт полный доступ к базе.
2. Скопируйте **Project URL** (`https://....supabase.co`).
3. Эти два значения публичные, их можно прислать мне в чат, и я сам впишу их в `config.js`. Или впишите сами: на GitHub откройте `config.js` → карандаш → вставьте в кавычки → **Commit changes**.

Через минуту сайт обновится. На экране входа появятся поле для почты, кнопка **«Получить код в Telegram»** и кнопка **«Зарегистрироваться по почте»**.

Проверьте сами: зарегистрируйтесь со своей почтой, подключите Telegram, выйдите и войдите снова с кодом из Telegram.

## Шаг 8. Вход через Google (15 минут, бесплатно)

Этот шаг можно сделать позже. Пока его нет, кнопка «Войти через Google» покажет «Вход через Google ещё не включён на сервере», а всё остальное работает.

**А. Узнать адрес возврата в Supabase**
1. Supabase → **Authentication** → **Sign In / Providers** → **Google**.
2. Там есть поле **Callback URL (for OAuth)** вида `https://....supabase.co/auth/v1/callback`. Скопируйте его, оно нужно в пункте В. Окно пока не закрывайте.

**Б. Создать проект в Google Cloud** (банковская карта не нужна)
1. Зайдите на **console.cloud.google.com** под своим Google-аккаунтом. Если попросит, согласитесь с условиями.
2. Вверху слева выбор проекта → **New project** → имя `go-transfer-go` → **Create**. Убедитесь, что вверху выбран этот проект.
3. В поиске вверху наберите **Google Auth Platform** и откройте его → **Get started**:
   - App name: `go-transfer-go`
   - User support email: ваша почта
   - Audience: **External**
   - Contact information: ваша почта
   - Поставьте галочку согласия → **Create**.
4. Слева **Audience** → кнопка **Publish app** → **Confirm**. Без этого войти смогут только люди из списка тестировщиков. Проверка Google тут не нужна: мы берём только почту и имя.

**В. Создать ключ для входа**
1. Слева **Clients** → **Create client**.
2. Application type: **Web application**, Name: `go-transfer-go сайт`.
3. **Authorized JavaScript origins** → **Add URI** → `https://autovinzare-code.github.io`
4. **Authorized redirect URIs** → **Add URI** → вставьте Callback URL из пункта А.
5. **Create**. Google покажет **Client ID** (длинный, кончается на `.apps.googleusercontent.com`) и **Client secret** (`GOCSPX-...`).
   **Client secret это секрет.** Не пересылайте его никому, даже мне, и не вставляйте в GitHub. Он нужен только в Supabase.

**Г. Включить Google в Supabase**
1. Вернитесь в Supabase → **Authentication** → **Sign In / Providers** → **Google**.
2. Включите **Enable Sign in with Google**, вставьте **Client ID** и **Client Secret** → **Save**.
3. **Authentication** → **URL Configuration**:
   - **Site URL**: `https://autovinzare-code.github.io/dzhipies/`
   - **Redirect URLs** → **Add URL** → `https://autovinzare-code.github.io/dzhipies/` → **Save**.
   Без этого Google после входа вернёт человека не туда.

Проверьте сами: на сайте нажмите «Войти через Google», выберите аккаунт, впишите имя. Вы внутри.

Когда переедем на свой домен, добавьте новый адрес в пункт В.3 (в Google) и в Redirect URLs (в Supabase).

## Где лежат секретные ключи

| Ключ | Где хранится | Можно ли показывать |
|---|---|---|
| Токен бота (`7123456789:AAH...`) | только Supabase → Edge Functions → Secrets | **Нет.** Никому, даже мне. Не вставлять в GitHub. |
| `TELEGRAM_WEBHOOK_SECRET` | только Supabase → Secrets | **Нет.** |
| Ключ `secret` / `service_role` | только внутри Supabase, функция берёт его сама | **Нет.** Даёт полный доступ к базе. |
| Пароль базы данных | ваши заметки или менеджер паролей | **Нет.** |
| SMTP-ключ Brevo | только Supabase → Authentication → SMTP | **Нет.** |
| Google Client secret (`GOCSPX-...`) | только Supabase → Authentication → Google | **Нет.** |
| Project URL и Publishable / anon key | `config.js` на GitHub | Да, они публичные. Без входа они ничего не открывают. |

Если кажется, что секрет утёк (переслали в чат, вставили в GitHub):
- токен бота: в @BotFather → `/revoke` → выберите бота → новый токен вставьте в Secrets → откройте ещё раз адрес из шага 5, пункт 7;
- ключ `secret` / `service_role`: Supabase → Project Settings → API Keys → создать новый и удалить старый;
- SMTP-ключ: в Brevo удалите старый ключ и создайте новый;
- Google Client secret: Google Cloud → Google Auth Platform → Clients → ваш ключ → **Add secret**, новый вставьте в Supabase, старый удалите;
- `TELEGRAM_WEBHOOK_SECRET`: придумайте новый, сохраните в Secrets и откройте адрес из шага 5, пункт 7 с новым секретом.

Также включите двухфакторный вход (2FA) на аккаунтах GitHub, Supabase, Brevo, Google и Telegram (Telegram → Настройки → Конфиденциальность → Облачный пароль). Через эти аккаунты можно добраться до всего проекта.

## Если вы уже настраивали сервер раньше

Повторите шаг 3 (запустите новый `schema.sql`, он ничего не удаляет) и шаг 5, пункты 1–4 (вставьте новый код функции `tg-login` и нажмите Deploy).

## Важно знать про бесплатный тариф Supabase

- База до 500 МБ, 50 000 активных пользователей в месяц: для старта хватит с запасом.
- **Если неделю никто не заходил, проект ставится на паузу.** Его включают кнопкой **Restore** в панели Supabase. Когда пользователей станет много, этого не будет. Позже можно перейти на Pro (25 $ в месяц), и пауз не будет совсем.
- На бесплатном тарифе нет резервных копий, которые можно скачать. Когда появятся первые настоящие пользователи, настроим ежедневную выгрузку базы (тоже бесплатно, через GitHub Actions).

## Если что-то не работает

- «Сервер ещё не настроен: включите анонимный вход» → шаг 4, пункт 2.
- Бот не отвечает на «Старт» → откройте ещё раз адрес из шага 5, пункт 7. Проверьте, что Verify JWT выключен.
- Код в Telegram не приходит → проверьте, что Telegram подключён (в профиле строка «Telegram подключён») и что вы не заблокировали бота. Если заблокировали, откройте бота, нажмите «Старт» и запросите код ещё раз. Больше 10 кодов в час на один аккаунт бот не присылает.
- Письмо с кодом не приходит → проверьте «Спам» и настройки SMTP в шаге 6. В Brevo в разделе **Transactional → Logs** видно, ушло ли письмо.
- «Вход через Google ещё не включён на сервере» → шаг 8, пункт Г.
- Google пишет `redirect_uri_mismatch` → в шаге 8, пункт В.4 адрес не совпадает с Callback URL из Supabase. Скопируйте его ещё раз.
- После Google человек попадает на чужую страницу или на главную без входа → шаг 8, пункт Г.3 (Redirect URLs).
- Google пишет «403 disallowed_useragent» → сайт открыт внутри Telegram, Instagram или Facebook. Google там вход запрещает. Откройте сайт в Chrome или Safari.
- Всё равно не работает → напишите мне, что видите на экране.
