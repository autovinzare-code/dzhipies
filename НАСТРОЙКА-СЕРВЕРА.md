# Как включить настоящий сервер и вход через Telegram

Всё бесплатно. Займёт около 30–40 минут. Делается один раз.

Что получится: люди входят через Telegram-бота (или по коду на почту, если Telegram нет), а маршруты, точки ожидания, брони, чаты и отзывы сохраняются на сервере и видны всем.

Пока вы это не сделаете, сайт работает как раньше, в демо-режиме.

---

## Шаг 1. Создать Telegram-бота (5 минут)

1. Откройте Telegram и найдите **@BotFather** (с синей галочкой).
2. Отправьте ему `/newbot`.
3. Он спросит имя. Напишите, например: `go-transfer-go вход`.
4. Он спросит адрес бота. Он должен заканчиваться на `bot`, например: `gotransfergo_login_bot`.
5. BotFather пришлёт **токен**: длинную строку вида `7123456789:AAH...`.
   **Это секрет.** Никому его не пересылайте, в том числе мне, и не вставляйте в GitHub. Он понадобится в шаге 4.

## Шаг 2. Создать проект Supabase (5 минут)

1. Зайдите на **supabase.com** → **Start your project** → войдите через GitHub.
2. **New project**:
   - Name: `go-transfer-go`
   - Database Password: нажмите **Generate**, сохраните пароль у себя (в заметки или менеджер паролей).
   - Region: **Central EU (Frankfurt)**. Данные европейцев должны храниться в ЕС.
   - Тариф **Free**.
3. Подождите 1–2 минуты, пока проект создаётся.

## Шаг 3. Создать таблицы (2 минуты)

1. Слева **SQL Editor** → **New query**.
2. Откройте файл [`supabase/schema.sql`](supabase/schema.sql) в репозитории на GitHub, нажмите кнопку «Copy raw file» (две квадратные рамки) и вставьте всё в окно Supabase.
3. Нажмите **Run**. Должно появиться `Success. No rows returned`.

## Шаг 4. Включить вход

1. Слева **Authentication** → **Sign In / Providers** (или **Settings**).
2. Включите **Allow anonymous sign-ins** и нажмите **Save**. Это нужно для технической сессии до входа. Без номера телефона человек ничего не сможет опубликовать или прочитать.
3. Там же проверьте, что **Email** включён (по умолчанию так и есть).

## Шаг 5. Загрузить функцию входа через Telegram (5 минут)

1. Слева **Edge Functions** → **Deploy a new function** → **Via Editor**.
2. Имя функции: `tg-login` (ровно так).
3. Удалите пример кода, откройте [`supabase/functions/tg-login/index.ts`](supabase/functions/tg-login/index.ts) на GitHub, скопируйте и вставьте всё.
4. Нажмите **Deploy function**.
5. Откройте функцию → **Details** (или **Settings**) → выключите **Enforce JWT verification** / **Verify JWT** → **Save**.
   Это нужно, потому что сообщения от Telegram приходят без ключа Supabase. Функция сама проверяет каждое сообщение секретом из следующего пункта.
6. Слева **Edge Functions** → **Secrets** → добавьте три секрета:

   | Name | Value |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен из шага 1 |
   | `TELEGRAM_WEBHOOK_SECRET` | придумайте длинный пароль из латинских букв и цифр, 30+ символов, без пробелов. Например, наберите случайно на клавиатуре. |
   | `ALLOWED_ORIGIN` | `https://autovinzare-code.github.io` |

7. Подключите бота к функции. Откройте в браузере адрес (подставьте своё):
   ```
   https://АДРЕС-ПРОЕКТА.supabase.co/functions/v1/tg-login?setup=ВАШ_TELEGRAM_WEBHOOK_SECRET
   ```
   Адрес проекта смотрите в **Project Settings → Data API → Project URL**.
   Должно появиться: **«Готово! Бот @… подключён.»**

## Шаг 6. Вход по почте для тех, у кого нет Telegram (10 минут)

Встроенная почта Supabase отправляет всего пару писем в час и только вам самим. Поэтому подключаем бесплатный сервис писем **Brevo** (300 писем в день бесплатно).

1. Зарегистрируйтесь на **brevo.com** (тариф Free).
2. **Senders, Domains & Dedicated IPs** → **Senders** → добавьте адрес, с которого будут идти письма (например, ваш Gmail), и подтвердите его по ссылке из письма.
3. Справа вверху меню → **SMTP & API** → вкладка **SMTP**: там указаны сервер `smtp-relay.brevo.com`, порт `587`, логин, и кнопка **Generate a new SMTP key**. Создайте ключ.
4. В Supabase: **Authentication** → **Emails** → **SMTP Settings** → включите **Enable custom SMTP** и впишите:
   - Sender email: адрес из пункта 2
   - Sender name: `go-transfer-go`
   - Host: `smtp-relay.brevo.com`, Port: `587`
   - Username: логин из Brevo, Password: SMTP-ключ из Brevo
   - **Save**
5. Там же **Authentication** → **Emails** → **Templates**. В шаблонах **Magic Link** и **Confirm signup** замените текст на:
   - Subject: `Код для входа в go-transfer-go`
   - Body:
     ```html
     <h2>Ваш код: {{ .Token }}</h2>
     <p>Введите его на сайте go-transfer-go. Код действует 10 минут. Если вы не входили, просто удалите это письмо.</p>
     ```
   Без этого в письме будет ссылка вместо кода.
6. **Authentication** → **Sign In / Providers** → **Email** → **Email OTP Expiration**: поставьте `600` (10 минут) → **Save**. Так украденный старый код быстро становится бесполезным.

## Шаг 7. Подключить сайт к серверу (2 минуты)

1. В Supabase: **Project Settings** → **API Keys**. Скопируйте **Publishable key** (`sb_publishable_...`) или, если его нет, ключ **anon public**.
   **Не берите** ключ `secret` / `service_role`: он даёт полный доступ к базе.
2. Скопируйте **Project URL** (`https://....supabase.co`).
3. Эти два значения публичные, их можно прислать мне в чат, и я сам впишу их в `config.js`. Или впишите сами: на GitHub откройте `config.js` → карандаш → вставьте в кавычки → **Commit changes**.

Через минуту сайт обновится. На экране входа появится кнопка **«Войти через Telegram»**.

## Важно знать про бесплатный тариф Supabase

- База до 500 МБ, 50 000 активных пользователей в месяц: для старта хватит с запасом.
- **Если неделю никто не заходил, проект ставится на паузу.** Его включают кнопкой **Restore** в панели Supabase. Когда пользователей станет много, этого не будет. Позже можно перейти на Pro (25 $ в месяц), и пауз не будет совсем.
- На бесплатном тарифе нет резервных копий, которые можно скачать. Когда появятся первые настоящие пользователи, настроим ежедневную выгрузку базы (тоже бесплатно, через GitHub Actions).

## Если что-то не работает

- «Сервер ещё не настроен: включите анонимный вход» → шаг 4, пункт 2.
- Бот не отвечает на «Старт» → откройте ещё раз адрес из шага 5, пункт 7. Проверьте, что Verify JWT выключен.
- Письмо с кодом не приходит → проверьте «Спам» и настройки SMTP в шаге 6. В Brevo в разделе **Transactional → Logs** видно, ушло ли письмо.
- Всё равно не работает → напишите мне, что видите на экране.
