# Безопасность go-transfer-go

Простая памятка: что уже защищено в демо и что обязательно сделать, когда появятся настоящий сервер, SMS и оплата. Основа: OWASP Top 10 (2021/2025), OWASP ASVS 4/5, OWASP MASVS для мобильных приложений, требования GDPR и закона Молдовы о персональных данных (133/2011).

## Что уже сделано в демо

| Угроза | Защита |
|---|---|
| Взлом через чужой код в тексте (XSS) | Всё, что пишет человек (имя, чат, отзывы, адреса), выводится только после экранирования `esc()`. Картинки принимаются только как `data:image/...` (`safeImg`). |
| Подмена кода на CDN | У d3 и MapLibre стоит отпечаток (SRI, `integrity`). Если файл на CDN изменят, браузер его не запустит. |
| Загрузка вредного кода со сторонних сайтов | Политика CSP в `<meta>`: код только с cdnjs и unpkg, данные только с OpenFreeMap, OSRM, Nominatim и Supabase (`*.supabase.co`); запрещены плагины (`object-src 'none'`), подмена базового адреса (`base-uri 'none'`) и отправка форм на чужие сайты (`form-action 'none'`). |
| Перехват вкладки через внешние ссылки | Все ссылки наружу открываются с `rel="noopener noreferrer"`. |
| Подмена кодировки | `<meta charset="utf-8">` в самом начале страницы. |
| Огромные тексты и файлы | Все поля имеют предел длины; фото до 15 МБ и пересжимаются через canvas (это заодно удаляет из фото GPS-координаты и другие скрытые данные EXIF). |
| Неверные числа | Места, кг, машины и цены проверяются на разумные пределы, дата выезда не может быть в прошлом. |
| Испорченные данные в браузере | Если сохранённые данные повреждены, приложение берёт значения по умолчанию, а не ломается. |

## Сервер и вход (Supabase + Telegram)

Настройка: [НАСТРОЙКА-СЕРВЕРА.md](НАСТРОЙКА-СЕРВЕРА.md). Пока `config.js` пустой, сайт работает в демо-режиме.

| Угроза | Защита |
|---|---|
| Вход от чужого имени | Номер приходит только из Telegram (кнопка «Поделиться номером», проверяется, что это номер самого отправителя). Ссылка на бота одноразовая: 256 бит случайности, в базе хранится только её SHA-256, живёт 10 минут и привязана к сессии браузера, который её запросил. |
| «Подсунуть» человеку свою ссылку входа | Бот показывает код сверки и просит подтвердить вход кнопкой; на сайте виден тот же код. Кнопка «Это не я» отменяет вход. |
| Поддельные сообщения от «Telegram» | Функция принимает обновления только с секретом `X-Telegram-Bot-Api-Secret-Token` (сравнение за постоянное время). |
| Вход по почте | Код из 6 цифр от Supabase Auth, срок 10 минут, встроенные лимиты на отправку и проверку. Номер у таких людей помечен как «не подтверждён». |
| Доступ к чужим данным (OWASP A01) | Row Level Security на всех таблицах. Чат и брони видят только две стороны. Телефон и Telegram ID закрыты на уровне столбцов, телефон отдаётся только второй стороне брони через `booking_phone()`. |
| Подмена имени, владельца, мест | Владельца, имя водителя, имя в отзыве и время ставит сервер (триггеры). Свободные места меняются только функцией `book_route()` в одной транзакции. Значок «Проверен» браузер поменять не может. |
| Фальшивые отзывы | Отзыв только после своей брони и только один на бронь. |
| Спам | Лимиты: 20 объявлений и 20 точек ожидания в сутки, 20 сообщений в минуту и 500 в сутки, 30 броней в сутки, 5 попыток входа за 10 минут. |
| Мусорные данные | Проверки в базе: координаты, места в пределах, длина текстов, размер фото, только `data:image/...`. В браузере всё снова проверяется перед выводом (`esc`, `safeImg`, `okPt`). |
| Секреты | Токен бота и секрет вебхука только в Secrets Supabase. В `config.js` лежит только публичный ключ, он ничего не открывает без RLS. |
| Право на удаление (GDPR, закон РМ 133/2011) | Кнопка «Удалить аккаунт и все данные» и «Выйти на всех устройствах». |

Осознанное отступление от пункта «сессия в HttpOnly cookie»: на GitHub Pages нет своего сервера, поэтому токен Supabase хранится в `localStorage`. Он живёт 1 час и обновляется; от кражи через XSS защищают CSP и экранирование. При переезде на свой домен и сервер стоит перенести сессию в cookie.

Что ещё сделать при росте: капча Cloudflare Turnstile для анонимных сессий и писем (Supabase → Auth → Attack Protection), периодическая чистка анонимных пользователей без профиля, фото в Supabase Storage вместо базы.

## Ограничения GitHub Pages

GitHub Pages не даёт ставить свои HTTP-заголовки. Поэтому нельзя включить:
- `frame-ancestors` / `X-Frame-Options` (защита от встраивания сайта в чужую рамку, «кликджекинг»);
- `Strict-Transport-Security` (HSTS) с preload;
- `Permissions-Policy`, `X-Content-Type-Options`.

Решение при запуске: поставить сайт за Cloudflare (бесплатно) или перенести на Netlify / Cloudflare Pages / свой сервер и задать эти заголовки там. Пример набора:

```
Content-Security-Policy: (как в index.html) + frame-ancestors 'none'
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(self), payment=(self)
Cross-Origin-Opener-Policy: same-origin
```

Важно: все сайты на `autovinzare-code.github.io/...` делят одно «происхождение» (origin) и общее хранилище браузера. Не размещайте на этом адресе чужие или экспериментальные страницы. Для настоящего запуска нужен свой домен.

## Чек-лист перед настоящим запуском (сервер, SMS, оплата)

### 1. Вход и аккаунты (OWASP A07)
- SMS-код: 6 цифр, живёт 5 минут, максимум 5 попыток, затем блок на 15 минут.
- Лимит отправки SMS на номер и на IP (защита от «SMS-бомбинга» и списания денег за SMS). Включить капчу (Cloudflare Turnstile) после 2-й попытки.
- Сессия в cookie с флагами `HttpOnly; Secure; SameSite=Lax`, не в localStorage.
- Выход со всех устройств, срок жизни сессии, новый идентификатор сессии после входа.

### 2. Доступ к данным (OWASP A01, самая частая уязвимость)
- Сервер проверяет КАЖДЫЙ запрос: можно ли этому человеку видеть или менять эту бронь, чат, маршрут. Нельзя доверять номеру (id) из адреса или запроса.
- Телефон водителя отдаётся только после оплаченной брони.
- Админ-панель только с двухфакторным входом и отдельного адреса.

### 3. Ввод данных (OWASP A03)
- Все запросы к базе только через параметры (prepared statements / ORM), никогда не склеивать SQL из текста.
- Проверять длину, тип и пределы на сервере (проверка в браузере обходится за минуту).
- Фото: проверять реальный тип файла, пересжимать на сервере, удалять EXIF, хранить в отдельном хранилище (S3/R2) с другого домена.

### 4. Оплата 1 лей (PCI DSS)
- Никогда не принимать номер карты на своём сайте. Только платёжная страница или виджет провайдера (Stripe Checkout, MAIB, Paynet).
- Бронь подтверждается только по серверному уведомлению (webhook) от платёжки с проверкой подписи, а не по сообщению из браузера.
- Защита от повторного списания: ключ идемпотентности на каждый платёж.

### 5. Секреты и сервер (OWASP A02, A05)
- Ключи API, пароли от базы, токены SMS-сервиса только в переменных окружения или менеджере секретов. Никогда в GitHub.
- Включить в GitHub: Secret scanning, Dependabot alerts, двухфакторный вход для аккаунта.
- Только HTTPS (TLS 1.2+), база недоступна из интернета, ежедневные резервные копии с проверкой восстановления.
- Обновлять зависимости (OWASP A06), `npm audit` / `pip-audit` в каждой сборке.

### 6. Защита от атак и вирусов
- Cloudflare (WAF + защита от DDoS + лимиты запросов) перед сервером.
- Загруженные файлы проверять антивирусом (ClamAV) и никогда не исполнять.
- Журналы входов, ошибок доступа и платежей (OWASP A09), оповещение при всплесках. В журналы не писать коды SMS, пароли и номера карт.
- Сервер не ходит по ссылкам, которые прислал пользователь (OWASP A10, SSRF).

### 7. Персональные данные (GDPR, закон РМ 133/2011)
- Политика конфиденциальности и согласие при регистрации.
- Собирать минимум данных; кнопка «удалить аккаунт и все данные»; выгрузка своих данных по запросу.
- Хранение в ЕС, договор обработки данных (DPA) с каждым сервисом (SMS, хостинг, оплата).
- Сообщать о утечке в надзорный орган в течение 72 часов.

### 8. Мобильное приложение (OWASP MASVS)
- Токены в Keychain / Android Keystore, не в обычном хранилище.
- Без ключей и секретов внутри приложения.
- Проверка сертификата сервера, запрет HTTP.

### 9. Регулярно
- Раз в квартал: проверка сайта сканером (OWASP ZAP, Mozilla Observatory, securityheaders.com).
- Перед большим запуском: внешний аудит (пентест).
- Файл `/.well-known/security.txt` с почтой для сообщений об уязвимостях.
